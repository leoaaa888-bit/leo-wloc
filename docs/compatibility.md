# 系统兼容性

这一页只讲一件事: **在你的系统版本上, 这个项目能不能用。**

## 结论速查

| iOS 版本 | 能否工作 | 需要重启设备吗 |
| --- | --- | --- |
| iOS 15 ~ 18 | 可以 | 通常不需要 |
| iOS 26.x | 可以 | **需要** |
| iOS 27 beta 6 及以后 | **不能** | — |

上面的分界来自上游项目的实测报告。**本项目未独立复验**, 下面会说明依据和它的局限。

## iOS 27: MITM 在 TLS 证书校验层被挡

上游项目在其 README 中报告: 从 iOS 27 beta 6 起, `gs-loc.apple.com` /
`gs-loc-cn.apple.com` 无法再被 MITM 拦截。beta 8 上的进一步测试指向具体原因:

- `locationd` 仍然正常走系统代理 —— 请求确实到得了中间人
- 但它**拒绝任何非 Apple CA 签发的证书**
- 即使该 CA 已在「设置 → 通用 → 关于本机 → 证书信任设置」里打开完全信任也不行
- 同一台设备、同一张 CA 证书拦截其它域名是成功的 —— 所以不是证书安装的问题

### 为什么换工具、换方案都没用

校验发生在**设备内部的 `locationd` 进程里**。这意味着:

- 换代理工具 (Surge → Shadowrocket → Loon …) 无效 —— 它们生成的都是自签 CA
- 软路由 / 网关侧透明代理无效 —— 改变的只是流量路径, 问题出在路径终点
- 自建 DNS 劫持 + 自签证书无效 —— 同上
- 越狱环境下或许有别的办法, 但那超出本项目范围

能做的只有: **停留在受影响版本之前的系统**, 或者接受这个功能不可用。

### 这个结论有多可靠

需要说清楚:

- 这是**转述**上游的实测记录, 不是本项目的测量结果
- 上游项目已从 GitHub 下线, 其 issue 讨论无法再查阅, 只剩镜像里的 README 文字
- 具体在哪个 beta 版本引入、正式版是否保留、是否有区域差异, 都**没有**可核对的
  一手资料

如果你手上正好有受影响的系统, 实测结果欢迎反馈。

## iOS 26: 定位缓存必须靠重启清掉

从 iOS 26 起, Apple 大幅强化了 `locationd` 的定位缓存: 系统会把之前获取的真实定位
结果留在内存里并长时间复用。

表现是: 脚本日志明明显示「已改写」, 地图里的位置却纹丝不动。

**只有重启设备能清掉它。** 以下方式在 iOS 26+ 都**无效**:

- 开关飞行模式
- 关闭再打开定位服务
- 杀掉地图 App 重开
- 切换 WiFi / 蜂窝网络

### 成功率最高的操作顺序

**方法一 (推荐)**

1. 先在选点页面选好位置并「储存到设备」
2. 开飞行模式 → 关闭定位服务 → **重启设备**
3. 关闭飞行模式 (WiFi 也保持关闭) → 连上代理工具, 确认 VPN 图标出现 → 打开定位服务
4. 打开地图验证

关 WiFi 是有意的: 只走蜂窝时系统更依赖 WLOC, 更容易立刻触发一次新的网络定位请求。

**方法二**

1. 关闭定位服务
2. 在选点页面选好位置并储存
3. 打开定位服务 → 弹出「允许访问位置信息」时选 **「下次询问或在我共享时」**
4. 打开地图验证

## 代理工具兼容性

五个平台的 `$done` 约定各不相同, 这是脚本最容易出错的地方。本项目对每个平台都有
自动化测试覆盖 (`test/wloc.test.mjs`)。

| 工具 | 存储 API | 响应脚本的 `$done` | 请求脚本的 `$done` | 模块参数 |
| --- | --- | --- | --- | --- |
| Shadowrocket | `$persistentStore` | `{response}` | `{response}` | 支持 |
| Surge | `$persistentStore` | `{response}` | `{response}` | 支持 |
| Loon | `$persistentStore` | `{response}` | `{response}` | 支持 |
| Stash | `$persistentStore` | **顶层** | `{response}` | 支持 |
| Quantumult X | `$prefs` | **顶层** | **顶层** | **不支持** |
| Egern | `$persistentStore` | `{response}` | `{response}` | 用 Surge 模块 |

注意两处容易踩的坑:

- **Stash 的两条路径不一样**: `http-response` 脚本要顶层字段, `http-request` 脚本
  要 `{response}` 包装。合并处理必然有一条是坏的。
- **Shadowrocket 也提供 `$environment["surge-version"]`**, 所以平台探测必须先认
  `$rocket`, 否则小火箭会被识别成 Surge。

### Quantumult X 的限制

QX 的 `rewrite_local` 脚本**不支持传参数**。所以 QX 用户:

- 不能通过模块参数设置坐标
- 只能用选点页面 (或快捷指令) 写入
- 没有写入过坐标时, 脚本处于透传状态, 不改定位

这是 QX 的机制限制, 不是本项目的缺陷。

## 浏览器要求

选点页面用到:

- `fetch` + CORS
- `localStorage` (收藏列表; 不可用时只是收藏功能失效, 不影响储存坐标)
- `navigator.geolocation` (「当前位置」按钮, 可选)
- Leaflet 1.9.4 (从 cdnjs 加载, 带 SRI 校验)

iOS Safari 15 以上均可。**页面必须在走代理的网络环境下打开** —— 否则「储存到设备」
那条请求不会被模块拦截, 页面会显示红色提示。
