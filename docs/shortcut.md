# 快捷指令: 从地图 App 直接设定位置

做好之后, 在苹果地图或高德里长按选点 → **共享** → 选你的快捷指令, 定位就切过去了,
不用打开选点页面。

> **为什么这里是教程而不是一条链接?**
> iCloud 快捷指令链接只能由「快捷指令」App 自己生成并上传到 iCloud, 无法由代码离线
> 构造。更重要的是: 别人分享的快捷指令内部写的是**他们的**服务器地址, 用了就等于
> 又挂上一个第三方运行时依赖。自己建一遍只要几分钟, 而且指向的是你自己的服务。

两条指令: 一条**设定位置**, 一条**恢复真实定位**。

---

## 一、wloc 设定位置

### 配置速查

| 项 | 值 |
| --- | --- |
| 名称 | `wloc 设定位置` |
| 在共享表单中显示 | **开** |
| 接受的输入类型 | **URL** 和 **文本** (其余全部关掉) |
| 动作数 | 4 |

两条要粘贴的 URL 模板:

```
https://leo-wloc.pages.dev/api/parse?u=
```

```
https://gs-loc.apple.com/wloc-settings/save?
```

> 自部署了就把第一条换成你自己的 Pages / Worker 域名。第二条**不要改** —— 它是被
> 你设备上的模块就地拦截的伪造端点, 这条请求从不离开设备。

### 逐步建立

**1. 新建并配置**

1. 打开「快捷指令」App → 右上角 **+**
2. 点顶部指令名 → **重命名** 为 `wloc 设定位置`
3. 点顶部指令名 → **详细信息** (ⓘ)
4. 打开 **在共享表单中显示**
5. 点下方出现的 **接受的输入类型**, 只勾选 **URL** 和 **文本**, 其余全部取消

**2. 添加动作 ①:URL 编码**

搜索并添加 **「文本」→「URL 编码」** (英文: *URL Encode*)

- 输入设为 **快捷指令输入** (Shortcut Input)
- 模式保持 **编码** (Encode)

> 这一步不能省。地图链接里带 `?` 和 `&`, 不编码直接拼进查询串, 后面的参数会被截断,
> 解析必然失败。

**3. 添加动作 ②:解析坐标**

添加 **「网页」→「获取 URL 内容」** (英文: *Get Contents of URL*)

URL 栏填:

```
https://leo-wloc.pages.dev/api/parse?u=
```

然后**紧接着**插入上一步的变量 **「URL 编码的文本」**。

拼出来的效果是 `https://leo-wloc.pages.dev/api/parse?u=［URL编码的文本］`。

> 这里**不加** `format=json`。不带 `format` 时接口直接返回 `lat=22.284774&lon=114.159437`
> 这样一段可以直接拼进下一条 URL 的查询串 —— 省掉解析 JSON 的两个动作。

**4. 添加动作 ③:写入设备**

再加一个 **「获取 URL 内容」**

URL 栏填:

```
https://gs-loc.apple.com/wloc-settings/save?
```

紧接着插入上一步的变量 **「URL 内容」** (Contents of URL), 再手打:

```
&acc=25
```

完整形态: `https://gs-loc.apple.com/wloc-settings/save?［URL内容］&acc=25`

想顺带开启坐标扰动就再加 `&randomRadius=200`。

**5. 添加动作 ④:显示结果**

添加 **「脚本」→「显示结果」** (*Show Result*), 内容用上一步的 **「URL 内容」**。

成功时会看到:

```json
{"success":true,"longitude":114.159437,"latitude":22.284774,"accuracy":25,...}
```

`"success":false` 或者干脆报网络错误, 说明模块没拦到, 见 [排查](troubleshooting.md)。

### 怎么用

- **苹果地图**: 长按地图选点 → 底部卡片上划 → **共享** → `wloc 设定位置`
- **高德地图**: 选点 → **分享** → **更多** → `wloc 设定位置`
- **Google Maps**: 选点 → **共享** → `wloc 设定位置`
- **百度地图**: 见下方注意事项
- 也可以直接复制一段链接或 `22.284774,114.159437` 这样的坐标文本, 在快捷指令 App 里
  手动运行

## 二、wloc 恢复真实定位

这条更简单, 只有两个动作, **不需要**共享表单。

| 项 | 值 |
| --- | --- |
| 名称 | `wloc 恢复定位` |
| 在共享表单中显示 | 关 |
| 动作数 | 2 |

**1.** 添加 **「获取 URL 内容」**, URL 填:

```
https://gs-loc.apple.com/wloc-settings/save?action=clear
```

**2.** 添加 **「显示结果」**, 内容为 **「URL 内容」**。

成功返回 `{"success":true,"cleared":true}`。

建议把它添加到主屏幕或放进小组件, 一键恢复。

> 清除之后脚本进入**透传**状态, 原样放行 WLOC 响应。**iOS 26+ 需要重启设备**才能清掉
> `locationd` 的定位缓存 —— 见 [系统兼容性](compatibility.md)。

---

## 三、可选: 查询当前生效坐标

同样两个动作, URL 用:

```
https://gs-loc.apple.com/wloc-settings/save?action=query
```

返回当前存着的坐标, 或者 `{"success":false,"error":"无已保存的坐标"}`。

## 各家地图的注意事项

| 来源 | 情况 |
| --- | --- |
| **苹果地图** | 链接里直接带 `coordinate=`, 但在中国大陆是 GCJ-02 偏移坐标, 由解析接口换算。港澳台发的是 WGS84, 自动跳过换算。 |
| **高德** | 分享出来是短链, 真实坐标藏在 302 跳转里, 由解析接口跟跳转取出, 并做 GCJ-02 → WGS84。 |
| **Google Maps** | 优先取地点针脚 `!3d!4d`, 而不是相机视口 `@` —— 后者跟缩放级别绑定, 可能离目标十几公里。 |
| **百度** | 大陆 POI 可以解析。**港澳台的分享短链不行** —— 那些坐标要靠网页脚本带反爬令牌去查, 服务端复现不了。变通办法: 在浏览器打开该链接, 等地址栏变成 `map.baidu.com/poi/名称/@数字,数字,19z` 之后复制整条地址。另外百度针脚与苹果/高德常有几十到两百米出入, 要精确定位不建议用它。 |
| **纯文本坐标** | `22.284774,114.159437` 视为已是 WGS84, 不做任何换算。 |

## 排错

**快捷指令报网络错误 / 无法连接**

那条 `gs-loc.apple.com` 请求需要走代理并被模块拦截。确认:

1. 代理已连接 (状态栏有 VPN 图标)
2. 模块已启用, MITM 已开
3. CA 证书已在「证书信任设置」里**完全信任**

**解析接口返回 `{"error":"未能从链接中解析出经纬度"}`**

这条链接里没有可提取的坐标。试试在地图 App 里换一种分享方式 (「共享地点」而不是
「共享导航」), 或者直接复制坐标文本。

**设定成功但定位没变**

iOS 26+ 的定位缓存问题, **必须重启设备**。见 [系统兼容性](compatibility.md)。
